# 本机消息历史前端操作

消息历史使用后端白名单作为采集许可。先填写平台、账号 ID、会话类型与外部会话 ID，再显式批准记录并保存白名单；前端不读取联系人列表。后端新策略默认不记录、不分析；现有页面的记录复选框需由用户确认。开启分析表示同意把该会话文本发送给后端配置的模型。

QQ Reader 每 10 秒读取一次已批准策略，只保存策略允许的后续消息；没有可用白名单时不入库。策略会缓存在本机 SQLite 中，以便后端短暂离线时继续遵循最近一次批准；撤销策略会在下一次成功轮询后停止后续采集和同步。离线时无法获知撤销，采集端会继续使用最近一次缓存许可。

本机通用 outbox 最多保留 10,000 条待发送消息；达到上限后 Reader 暂停读取并等待同步腾出空间，不静默删除历史。QQ/OneBot 不保证补拉断线或暂停期间的消息，因此本地队列满或连接中断时不能保证完整捕获。v1 模式下策略 revision 变更或撤销时，旧 revision 的未同步行会隔离，不会在重新批准后自动放行；v2 则以 capture_epoch 为采集许可边界。既有旧版消息表保留原样，不会批量迁移或回填到新后端。原始事件保存默认关闭。

在设置里的“消息历史”面板可以查看覆盖水位、摘要和事实，手动浏览最近原文、提交尾批分析或重试失败任务。管理令牌只在当前页面内存中使用，刷新页面后需要重新填写。它不是 QQ WebSocket Token，也不是消息导入专用 Token。QQ 登录、聊天数据库及真实消息不用于合成测试。

## R1 v2 协议（代码已就绪，当前一天采集进程未热更新）

后端与 Reader 同步升级后，可由本地管理 API 将某会话 minimum_import_version 显式设为 2。
本轮没有在真实白名单上执行升级，也未重启正在采集的 Windows 服务；现有页面暂未增加升级按钮。
上线前先确认待同步 outbox 已清空、同步后端代码并重启两端，再逐会话升级；升级不可降回 1。

v2 在采集时保存 capture_epoch，原生 OneBot 数组保留 at/all、reply 和有序 content_parts。
纯文本/CQ 字符串的元数据能力标为 unknown，不猜测 @ 或回复对象。批量大小等调度修改
不会隔离合法 v2 待同步消息；撤销记录再授权则递增 capture_epoch，旧队列永久隔离。
旧 v1 行不会补盖新 epoch，升级后不得重发旧行绕过新协议；混合队列按原版本分批同步。
媒体状态同步同样保留原始 capture_epoch 和版本，不将旧媒体标记成新的采集许可。

后端后台配置 API 现在包括独立 message_history 配置及 active/desired/restart_required。
更换服务商配置身份会在重启时关闭既有分析许可，需用户重新开启；更换模型只使旧分析
任务失效，不停止记录。现有摘要仍为 legacy-v1，不表示话题/重要性流水线已启用。

## R5 阅读中心（代码就绪，未重启采集进程）

沿用设置中消息历史入口，增加概览、话题、亮点、重要信息、事项候选五个视图。
界面使用原有纸色 #f5f8f8、白色 #ffffff、文字 #19313a、灰蓝 #58717a、
青色 #237b80 与边线 #d8e4e6；保留 Segoe UI / Microsoft YaHei 字体与左对齐层级。
布局为页签、会话/时间筛选、列表、展开详情；信息层级来自覆盖、原文与实际写入效果，
不改变整体聊天工作台，不增加自动动画或系统通知。

阅读 GET 不标已阅、不触发分析。重要信息的已阅/忽略/一小时后看是独立 CAS 操作，
不发送平台回执。按 certainty 展示明确和待核实两组；来源原文每页 20 条，使用 opaque
keyset cursor 加载下一页，不把原文嵌入完整列表。话题展示结论、分歧、参与数和覆盖；
亮点使用后台 highlight 分组，重要信息使用 importance 分组并默认仅未阅。
刷新列表不会覆盖已打开的详情或未提交审批表单。

后台区分别展示采集状态入口、本地扫描/分析/简报覆盖、预算用量、价格是否已知、
队列积压及失败原因。暂停/恢复带服务 revision；不改变采集许可。
会话表单允许显式设置最短分析间隔、尾批等待和事项候选许可；新会话默认不勾选记录。
模型、任务/服务/会话 token 和调用限额、共享每天费用上限保存为目标配置，
显示 active/desired/restart_required，不自行重启。费用门槛依赖后台已有有效价格配置。
关注设置只保存显式 JSON 字段，不扫描联系人或建立长期记忆。

审批预览展示精确证据和当前 proposal revision、preview_digest、evidence_digest。
创建仅保存用户编辑后确认的 title/summary/priority/due_at/tags；关联仅增加来源说明与
预览中已有事项目标/目标 revision；拒绝只携带拒绝原因。先预览实际载荷，再通过可信点击
确认一条。网络失败重试保留同一 decision_key；409 保留编辑但取消确认，必须重新载入
审批预览并重新核对。处理成功打开下一条候选详情，不自动批准。所有原文使用 textContent，
不执行聊天脚本、链接或 HTML，不提供自动分析或批量批准。

控制通道使用已经挂载的 /plugins/message-reading/ 白名单代理。
在前端服务的受保护启动环境配置独立 LKA_MESSAGES_CONTROL_TOKEN，并使后台使用同一值；
它不是 QQ/导入/API 令牌。不把它写入网页、浏览器存储、聊天提示、日志、工具输入输出或
Agent 可读配置文件。缺失时始终返回 401，不允许 loopback 无凭据降级。
原生 run-lka-native-windows.ps1 现已自动为两端配对：未显式设置启动环境时，按安装路径
和端口在 Windows LocalAppData/LKA/native-credentials 保存 CurrentUser DPAPI 加密文件，
随后仅向服务进程注入解密值。同一 Windows 用户的后续原生启动复用该凭据；不写入 .env。
其他启动方式仍须显式配对受保护环境，不能复用导入令牌。
可选 LKA_MESSAGE_READING_BACKEND_URL 默认 http://127.0.0.1:8765，只允许本机 HTTP 基地址。
代理验证 peer/Host/Origin，拒绝跨站请求、路径穿越、未知方法/路径/query、跨域配置修改，
输入最大 32 KiB、输出最大 1 MiB，不转发浏览器 Authorization/Cookie，
不跟随重定向、不回显后台错误正文。
Java 继续复用 requestMemory bridge，只将受限 /plugins/message-reading/ 路径发往前端服务，
不从浏览器或 Java 请求传递控制凭据；其他旧接口保留现有行为。

合成验证：tests/test_message_reading_proxy.py 使用独立 FastAPI ASGI 与 MockTransport，
不启动真实 QQ、数据库或模型。两份变更脚本使用已有 Windows Node runtime --check。
实现阶段仅修改源码。2026-10-04 21:40 经用户授权已部署原生前后端，并离线构建及重启
新版 Java 桥；三群升级 minimum_import_version=2，真实 @／回复元数据已到库。
服务状态与阅读 overview 经受限代理验收成功；实际 Java 页面点击与审批仍单独待验收。
同 OS 用户任意进程的隔离仍受后台设计所列安全边界限制。

协议升级前先排空旧正文及媒体队列并备份。已有确认的 v1 缓存只在相同已知 capture_epoch
下观察到合法 min1→min2 时取得单独字节保留许可，保留原 TTL，不重写旧元数据或重传媒体。
撤销记录／媒体或更换 epoch 会撤销缓存许可；TTL／额度仍清理。Windows 上媒体、协议及
新缓存保留的 27 项定向合成回归已通过；用例见 tests/test_message_media_retention.py。

显式关注配置还支持 critical_keywords；只有用户配置的本地规则可以提升 critical，
模型不能自行提升。重要信息和亮点详情中的“保存为本地评测样例”会先预览最多 20 条
精确来源，再由用户选择问题类型、填写说明并勾选本机原文复制许可后，通过可信点击保存。
预览绑定 evidence_digest；409 保留说明、清除旧预览与复制许可，要求重新核对。
样例存储仅在本机，不触发模型、上传、训练、反馈记忆或自动保存。新代理只增加
GET 列表/单条、POST 预览/保存的 evaluation/badcases 精确路径；没有上传或训练接口。


## 消息中心刷新

消息中心打开且页面可见时，会话记录数、待处理数量和阅读概览每 5 秒刷新。
群名和备注独立加载，不阻塞原文、阅读视图或自动刷新；手动备注优先。
QQ 群目录缓存 1 分钟，过期时在账号验证通过后先显示旧名称，并后台更新；
暂时故障仍显示 stale 状态并退避，账号不匹配时不显示缓存名称。
顶部“刷新”会同时刷新会话、名称和当前阅读列表。

自动刷新保留侧栏滚动位置、已加载会话和消息草稿，不覆盖已打开的详情。
阅读列表加载多页后暂停自动重载，保留已加载结果；点击顶部“刷新”重新获取第一页。
关闭消息中心或页面不可见时不继续发起轮询。刷新只更新展示，不改变后端分析进度。

合成回归入口：`npm run test:message-refresh`，覆盖慢备注、群名更新、实时数量、
手动刷新、分页、滚动、草稿、详情及关闭后停止请求。
