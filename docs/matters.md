# 待办与项目规划

工作台的清单入口打开完整待办页面，返回对话时保留原会话和输入。
桌宠快速窗口的清单按钮打开独立原生窗口，不随快速窗口收缩。
关闭原生待办窗口后保留页面、尺寸和未保存输入，再次点击聚焦已有窗口。
独立窗口使用定制标题栏、细边框和圆角，支持拖动、边缘缩放、最小化及双击标题栏最大化/恢复。

## 任务与规划

收集箱保存还未整理的想法；今天显示今天安排和今天截止的行动，逾期任务单独折叠。
接下来按日期查看未来事项。全部任务与完成记录分别管理当前行动和历史。
在输入框写下任务，回车添加；支持“明天 15:00 整理资料 45分钟”等简单表达，输入时显示解析日期。
悬停任务行可直接安排今天、明天或指定日期；完成和安排后的提示支持撤销，撤销也受版本检查保护。
点击任务打开详情，常用信息优先展示，时间与更多属性按需展开，保存按钮固定可见。
标题、搜索和快速添加固定在工作区上方，任务区与详情分别滚动。导航可手动收起并记住偏好；中等窗口展开详情时自动收窄导航，保留左右分栏。窄窗口使用可点击遮罩收起的详情抽屉，键盘焦点也限制在抽屉内。
快捷键：N 新建，Ctrl/Cmd K 搜索，Ctrl/Cmd Enter 保存，Esc 收起详情。

项目规划可以独立存在，用于学习、出行等目标，也可关联已有目录项目。
写下目标与完成标准，按阶段安排下一步，使用上下移动调整行动顺序，也可拖动任务到阶段。阶段标题的＋直接创建属于该阶段的行动；“添加阶段”就地录入名称。
规划进度由用户可见的直接行动计算，取消的行动不计入完成分母；完成规划不自动完成行动。
任务继承规划的目录；规划已有行动时需先移出行动才能更改目录。

## 日历

支持周、月和日程视图，显示全天任务、精确时间段与截止标记。周视图共享时间轴；月视图标明星期和今天，密集日期可展开更多事项，同日的安排与截止合并展示。
日历高度随可用空间调整，默认独立窗口可显示完整月份；短窗口减少每格直接展示的事项，通过“＋N项”访问其余记录。周历首次定位工作时间。
待安排区可搜索、折叠，拖放时突出目标日期；仅在工作区足够宽时放在右侧，详情展开或窄窗口时移至底部并默认收起。
“待安排”区域可把任务拖入日期或周时间格；也可通过日历安排表单或详情输入日期、时间和时长。
拖动已有时间段保留时长，拖到周全天区改为全天。移除安排只清空日程，保留任务和截止日期。
截止日期和计划时间分别保存；旧事项的截止日期不会自动变成日程。

## 对话与缓存

“对话管理”先通过 `/managers/default` 打开默认管理会话，不覆盖原对话草稿。
管理功能由后端配置选择启用；明确返回 `management_disabled`，或404后成功核实 OpenAPI 缺少管理接口且保留普通会话/Agent接口时，才沿用普通待办助手。全局助手入口不降级。
新管理会话默认暂停；页面显示状态，用户可明确启用管理写入或暂停管理，不因打开面板自动开启。
当前事项和规划的 ID、版本及视图选择随草稿传递，修改仍需查询核对与安全审查。描述目标、拆分行动或调整安排，
Agent 沿用已有工具、安全审查和确认流程；保存后界面增量同步同一份 matter 数据。
带消息历史来源的事项保持保护状态，请从消息中心通过专用人工审批处理。

事项列表、搜索、日历、统计及规划进度默认只投影 `visibility=user`（旧记录等同 user）。
授权同步仍缓存 internal 事项，显式内部展开可读取；内部行动不进入用户规划进度分母。
v2 缓存与旧缓存隔离，首次从零游标完整同步，之后同一 ID 按 revision 更新可见性。

页面先显示内存或本地持久化缓存，默认 60 秒有效期；有效期内重复打开不请求事项接口。
过期后后台增量同步，不清空已有列表。首次分页同步完整数据，再从游标增量更新，
按事项版本合并，跨页面通过存储事件及 BroadcastChannel 交换更新。
后端、访问上下文分别隔离；令牌仅存页面内存。缓存写入失败时继续使用内存。
这不是完整离线编辑队列：同步失败仍可查看已有内容，写入需连接后端。

编辑保存携带 `expected_revision`，只提交修改字段。冲突保留输入；“载入最新版本”合并其他入口的更新，
仍保留你的字段修改，核对后再保存。页面内可切换任务而保留草稿，刷新浏览器会丢失未保存输入。

## 接入与验证

`matters.html` 是独立窗口页面；工作台复用 `matters.js` / `matters.css`。
`matters-host.js` 适配现有请求桥，`matter-store.js` 管理缓存，`matter-calendar.js` 提供日历。
Java `PetMatterWindow` 的异步响应回到原请求窗口，凭据不进入 URL 或浏览器参数。
Python workbench 代理与 Java 桥仅开放已列入白名单的接口。

没有 UI 构建步骤。静态文件更新后刷新浏览器；Java 窗口代码更新后按日常启动流程重启前端和桌宠。
后端需提供新版日程字段和 `/matters/sync`；旧接口会显示同步错误并保留已有缓存。

合成验证不读取用户事项、不连接模型：

```sh
npm run test:matter-store
npm run test:matter-calendar
npm run test:matters
```

Java 21：`gradlew.bat -p desktop-pet-java verifyPetMatterWindow verifyPetMemoryBridge`。
真实页面验收：`gradlew.bat -p desktop-pet-java verifyPetMatterPage -PfrontendRoot=D:\lka-desktop\app\web\pet`。
浏览器测试需要 playwright-core 和 Chromium，支持 `PLAYWRIGHT_MODULE` / `CHROME_PATH`。
