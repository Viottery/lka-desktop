# 任务暂停、继续与打断

桌宠快速会话、电脑工作台和手机/平板使用同一套任务控制。
输入框旁只有一个按钮，根据任务状态和草稿在发送、暂停、继续图标之间切换。
工作台和手机的发送按钮使用与快速窗口一致的纸飞机图标。

## 使用

- **暂停**：任务运行中，输入框没有新内容时显示暂停图标。请求后按钮暂不可用，等待当前步骤结束；收到后端确认后才变为继续图标。当前模型请求或工具调用可能需要先结束。
- **继续**：任务暂停且输入框没有新内容时显示继续图标。接回原任务的运行编号和事件位置，沿用保存的执行进度，不会重新发送原问题。
- **发送新指令**：任务暂停后可以修改输入并用纸飞机发送。新指令替换暂停的任务，留在同一会话中；图片、文件和文字可以一起发送。
- **打断并替换**：仅在暂停后发送新内容时执行；使用后端原子替换接口结束旧任务、创建新任务。已经完成的操作和已有记录会保留，不执行撤销。

处理过程中输入框保持可编辑。输入新文字或加入附件后，暂停图标变回灰色纸飞机，但任务未暂停时仍不能发送，也不会因此打断任务。清空新内容后重新显示可点击的暂停图标。
暂停、继续和打断不会清空这份草稿。新指令发送失败时会保留原任务的暂停状态，恢复文字和附件，便于重试。
手机按钮保留至少 44px 的点击高度。Java 原生输入框旁的按钮也同步切换图标、悬浮说明和可用状态；没有增加额外的控制栏。

## 接口与事件

新任务通过 `/agent/turn/stream` 请求，并携带 `resumable: true`。
即使关闭逐字显示，仍订阅任务事件，回答在最终答案到达时显示。
旧 WebView 的非流式兼容入口也传递 `resumable`。

| 用户动作 | 后端接口 | 前端行为 |
| --- | --- | --- |
| 暂停 | `POST /agent/runs/{id}/interrupt` | `pause_requested` 只表示请求已接受，等待根运行 `run_paused` |
| 继续 | `POST /agent/runs/{id}/resume` | 返回值可能仍为 paused；随后连接原运行事件流，等待 `run_resumed` |
| 新指令 | `POST /agent/runs/{id}/replace` | 携带 `command_id`、原 `session_id`、附件与模型选项，使用返回的新 `run_id` |
| 打断并替换 | `POST /agent/runs/{id}/replace` | 暂停后发送新内容时，后端先结束旧运行再创建新运行 |
| 恢复显示 | `GET /agent/runs/{id}/stream?after_sequence=n` | 从保存的事件位置继续接收，校准最终答案与会话历史 |

暂停不是完成：事件流因暂停关闭时，不显示“本轮完成”、空答案或失败气泡。
恢复和替换使用独立订阅，并隔离旧运行的迟到事件。相同的新指令重试沿用同一个 `command_id`。
继续不会绕过原任务的安全审查或待回答问题，原有交互仍适用。

浏览器通过现有 `/workbench` 同源代理访问接口；代理新增精确的 interrupt/replace POST 路由。
Java 新增保存运行 SSE 桥接，使用配置的后端地址与 HTTP/1.1，转发事件名称、正文和序号。
关闭订阅只停止读取，不发送后端取消命令。QQ 和后端运行配置不受这项功能影响。

## 兼容与验证

后端需提供 interrupt/resume/replace/cancel 接口及可恢复检查点。
旧运行可能没有检查点；后端拒绝操作时，界面显示原因，保留现状，不会宣称任务已经暂停。
恢复网页后会读取保存的运行状态。不同设备控制同一运行时，界面也会定期读取后端状态。

隔离验证入口：

```powershell
npm run test:run-controls
npm run test:chat
npm run test:mobile
npm run test:images
.\desktop-pet-java\gradlew.bat -p desktop-pet-java --offline compileJava verifyPetRunStream
```

运行控制测试使用合成 HTTP/SSE 和原生桥接替身，不调用真实模型、不操作个人会话。
代理路由测试位于 `tests/test_workbench_proxy.py`。
