# 多端协同：云端、设备与账号

理事所可以连接一台云端（hub）和多台电脑（节点）。云端运行真理、待办、项目与记忆；
每台电脑保存自己的普通会话和文件。浏览器可以通过云端签发的一次性授权跳转到另一台电脑；设备页面与云端通信，但电脑节点不互相代理或同步普通会话。
后端接口与准入规则见 lka_backend 的 `docs/distributed_client_handoff.md`。
首次安装与 Ubuntu 云端静态页面部署见[部署说明](deployment.md)。

## 入口

| 入口 | 访问 | 能做什么 |
| --- | --- | --- |
| 桌宠与 Java 窗口 | 本机后端，以及云端真理 | 不提供设备跳转 |
| 电脑浏览器 | 目标电脑托管的工作台 `/desktop-pet/chat.html` | 从设备列表进入其他电脑 |
| 手机浏览器 | 目标设备托管的移动布局 | 同上 |

统一入口是云端的 `/desktop-pet/connect.html`：登录后点「进入」打开一台电脑。
入口向云端申请一次性授权，把授权放在地址的 `#` 片段中跳到那台电脑；电脑页面读取后立即清除，
兑换出这台电脑自己的连接（默认 30 天）。

切换只有一个入口：顶栏的位置标记显示当前在哪里（云端或某台电脑），点开列出可以去的地方——
云端工作台和每台已登记的电脑，当前所在处标为「当前」。选一台电脑会直接向云端申请授权并跳过去，
不用先回统一入口；云端未登录时，列表使用这个浏览器保存过的入口。菜单底部是「设备与账号」
（设备登记、真理派发、同步、共享记忆与账号）和「统一入口」。侧栏的「账号与管理」也打开同一个面板，
但不再重复设备切换。

真理和待办不区分在哪台电脑上：进入任何一台电脑后，只要云端连得上，侧栏的真理和待办都在，
对话和跟进直接来自云端；普通会话与文件仍属于这台电脑。云端暂时连不上时入口保留，
点开会提示云端离线，恢复后自动回来。同一浏览器只需登录一次：云端和电脑的登录都保存在
HttpOnly cookie 中，新标签页、从提醒打开的链接都会自动恢复身份和操作凭据。

云端暂时下线时，再次打开入口会列出这个浏览器进入过的设备。连接仍有效的设备可以直接打开；
已过期或被撤销的设备提示「需要通过云端重新进入」，不会改连到另一台电脑。

## 托管方式

云端和每台电脑都要在自己的 HTTPS 地址下提供 `app/web/pet`，二选一：

- 后端配置 `[client].workbench_dir = "<本仓库>/app/web/pet"`；
- 或用 Tailscale serve / 反向代理把 `/desktop-pet/` 指向该目录，其余路径转发到后端。

页面通过同源的 `/client/info` 判断角色。没有 `?host=` 参数、从 8780 前端服务打开时保持本机模式，
现有功能不变。

## 页面在不同位置的差异

- 云端页面：账号登录后可用真理、待办、项目、记忆，以及「设备与账号」面板中的设备、远程任务、同步与账号。
  消息与 QQ 依赖本机前端服务，云端页面不显示。
- 电脑页面：普通会话、工作区文件、共享记忆镜像、连接管理，以及来自云端的真理、待办和「设备与账号」面板。
  工作区是电脑批准的 ID，只有一个时自动使用，多个时在文件面板中选择；文件单个最多 32 MiB，
  只能新建，同名不覆盖。新运行强制人工审查，审批读取当前运行。
- 本机工作台：前端服务 `.env` 设置 `LKA_CLOUD_ORIGIN` 后，「账号与管理」可登录云端账号，
  顶栏随之出现位置标记，可在浏览器中打开云端工作台或其他电脑。Java 窗口不显示切换。
  默认只在前端服务内存保留登录。Windows 可设置 `LKA_CLOUD_SESSION_PATH`，
  由本机服务通过当前 Windows 用户的 DPAPI 加密保存会话令牌，重启后恢复；不保存密码，
  桌宠与本机浏览器共用这份服务端登录。测试与日常环境必须使用不同路径。
  凭据绑定云端 HTTPS 地址，退出、过期或云端返回 401 时清理；更换云端、Windows 用户或
  密文损坏后需要重新登录。未配置路径时维持内存模式，非 Windows 不提供明文降级。本机后端为节点时，真理、待办、项目与
  记忆经 loopback `/cloud` 网关来自云端；远程浏览器不能使用该网关。

## 设备面板

- 设备：登记（一次性令牌只显示一次）、编辑、撤销、轮换、撤销我的连接、连接偏好与解析测试。
- 远程任务：执行目标在线状态、任务结果分页、暂停/继续/取消、回答问题、审批与补充指令；
  命令 ID 在重试间保持不变，`resuming` 与 `unknown` 明确提示，不自动重放。
  真理跟进中的远程待确认提醒直接打开对应任务，显示设备、工具、参数和目标路径。
  批准后该项显示「已批准，等待设备处理」且不能重复提交；设备继续后自动刷新，
  下一项审批作为新的请求单独出现。提交失败会保留重试，并与「已提交未处理」区分。
- 真理跟进底部说明「启用管理」只允许整理与派发；任务完成后是否自动汇报取决于服务端
  `autonomous_enabled`，未开启时结果会等你下次发消息时处理。
- 同步：云端身份变化提示、设备候选的查看/拒绝、自动同步待核对的记忆。
- 共享记忆（电脑页面）：按全局/项目查看镜像，人工确认后排队修改，冲突保留提案并基于最新版本重新提交。
- 账号：退出、改密码（所有登录失效）、会话撤销、管理员增停与重置密码。

## 本地验证

```bash
npm run test:cluster   # 合成一个云端和两台电脑，1280 与 390 视口
```

测试只使用合成的本地服务和数据，覆盖登录、授权兑换重试、A/B 切换后会话与草稿隔离、
多工作区选择、同名上传 409、节点页面不调用云端专属接口、云端下线后的备用入口与连接失效提示。
截图写入 `.runtime/cluster-preview/`。真实 HTTPS、代理头、Tailscale 连通与 Service Worker
需要在实际部署后确认。
